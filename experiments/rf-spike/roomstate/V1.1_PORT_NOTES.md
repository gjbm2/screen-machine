### What changed
- **`roomstate/contract.py`** is now adapter contract v1.0:
  - `Reading` is unchanged. `Outcome` gains `retry=True`.
  - `Adapter` stays a base class with defaults for every §5.1 attribute, including `poll_inflight_s`, `read_timeout_s` (5), `dry_run` and `placeholder`.
  - New methods: `normalize()` (by default it checks `value_schema` and raises `ValueError`), `show()`, and `signal(member, action, args)`. `value_schema`, `actions` and `label` are kept from aa.
  - The §5.2 rules 1–11 are written in the module docstring as obligations, persistence included.
  - New `Placeholder(subsystem, members, values)`: `values` is a list for every member, or a map from member to list.
- **`roomstate/model.py`** is rewritten to the §2.4/§2.5 grammar:
  - `RoomConfig(raw, adapters, collect=False)`.
  - `Entry` and `verb()` are kept. `Step` gains `signal`, `subsystem`, `member`, `action`, `abort_on`, `rollback`, `allow_skipped` and `n`. `Mode` gains `family` and `descendants`. Rules are `Rule(from_, to, steps)` with a `catch_all` property.

  - New: `plan_steps` and `transition_for` take a from-set, a single name, or `None`. Also new: `cfg.is_concrete`, `cfg.concrete()`, `cfg.uses(slot, t)`, `sets_value(mode, t)` and `mode_signals(cfg, name, key)`.
- **`roomstate/schema.py`**: only `room_config_schema` changed. `class` is gone, `on_fail` takes the object form, `max_age_s` is allowed on retrieve only, options-only patch entries are accepted, signals can name a member, groups can be a single string, and `_` comment keys are allowed everywhere.
- **`roomstate/example_room.json`** is now the §2.2 example, word for word.
- **`rfspike/bloc_hub.py`**: I added only `BlocBlinds.normalize()`, which maps `"raised"`/`"lowered"` to 0/100. The load-time check needs it.
- **New `roomstate/tests/test_model_v11.py`** covers: specificity (in either key order), conflicts, prefixes at dot boundaries, wildcards, group-name rules, the four merge rules, entry checks, normalize at load (including `else`) with JSON pointers, the slot check, `@name` and descendants, a bare abstract name, the required catch-all, from-sets, `on_fail` forms, signal parsing, placeholders, v1 keys, `_` comments, all lint codes, the contract defaults and the JSON schema.

### Deviations
1. **Unknown subsystems, even bare names, become placeholders.** That is the literal reading of item 13 and §1.2. The catch is that a typo of a group name, such as `"privacy_blind"`, is accepted silently except for a `placeholder_values_unchecked` warning saying "no adapter". Making bare unknown names an error is a one-line change in `_select`.
2. **Placeholder members come from the config.** Dotted names the config uses for a placeholder that its device config doesn't list (`plug.dmx_power`) become members; when one name is a prefix of another, the longer one wins, so `sonos.lounge` stays a prefix. This needs a pre-scan, `_placeholder_members`, because modes are parsed one at a time. Without it, guards on placeholders would have no targets, which is the R8 hole.
3. **`slot_never_stored` is never emitted.** The new load error ("every retrieved slot/target must be stored by some mode") always fires first. `slot_never_retrieved` now works per slot and target.
4. **New lint code `falls_to_catch_all`.** §2.5 describes this warning but gives it no code. "A family with its own rules" here means a mode matched by any rule other than the catch-all.
5. **`else` is rejected on set and store entries**, like `max_age_s`. The spec lists it only as a retrieve option.
6. **What counts as an entry.** An object with any verb or option key is an entry, as in aa's code; merge rule 3 needs this for options-only patches. A plain object value that happens to have such a key must be written as `{"set": …}`.
7. **Three small extra checks** for obvious mistakes:
   - `abort_on` must name targets of its own step.
   - `on_enter`/`on_exit` accept only signals.
   - Groups can't nest (as in aa's code).
8. **Behaviour notes:**
   - `Adapter` stays a base class rather than a `typing.Protocol`, because the fakes and `BlocBlinds` subclass it.
   - `Mode.state` is in adapter target order, not JSON key order.
   - Signal actions are not checked against `adapter.actions`.
   - `rules()` still leaves out from == to, as aa's did.

### What the next stage must know
- **Building the config:** build `RoomConfig` from the adapters. `members_of`/`schemas_of` are no longer needed for it.
- **Placeholders live in the config:** `cfg.adapters` includes auto-created `Placeholder` objects (`placeholder=True`, kind `level`, no `read`/`apply`), and `cfg.members` lists them. The coordinator should take placeholders from there and check `a.placeholder` before `kind`.
- **Changed model API:**
  - `Mode.classes` and `Step.on_fail` are gone; use `abort_on`, `rollback` and `allow_skipped`.
  - `Step.action` is now just the action name; the full name is in `step.signal`.
  - Mode signals are a mode's own and are not inherited; use `mode_signals()` and `_edges`.
  - `cfg.transitions` holds `Rule` objects, and every rule's steps already end with a `rest` step, so the old `_steps()` should go.
- **Values:** entry values are already canonical.
- **Fakes:** `FakeLevel.signal(action, args)` and `FakeEdge` still use the v0.2 signature (item 24).
- **BlocBlinds:** the rest of v1.0 is not done: proof of arrival with `opts["pending"]`, `dry_run`/`writes_enabled`, re-send once, and STOP before re-targeting.

The runtime now matches spec v1.1, and the last full run was **205 passed, 0 failed** in 42 s. The machine was heavily loaded during that run (load average about 50 on 20 cores, from other sessions' ffmpeg jobs). I estimate about 25 s on an idle machine, but I didn't measure it.

### What changed

**`roomstate/state.py`**
- State file version 2: written atomically, file mode 0600, directory 0700, and only when the content changed.
- A file with an unknown version, or one that won't parse, is moved aside to `state.json.bad-<epoch>`. The reason goes into the coordinator's log.
- It writes compact JSON. An indented dump took about 19 ms per save here (the pure-Python encoder); compact takes about 1 ms.

**`roomstate/coordinator.py`** (rewritten to §4)
- **Tasks and locks:** `_req`, `_work`, `_task`, `_rtasks`, `_gen`, `_moving`, adapter health, and `_stop_tasks` with the 3 s cleanup bound.
- **Requests:** `request_mode` / `_request` per §4.2 (re-apply, `via`, carry-on and `resumes`, finalising a record whose task never ran, reserved sources).
- **Running:** `_run` / `_run_one` per §4.3, with every row written as `pending` at the start. `_plan()` is shared with `plan()`.
- **Store and send:** `_store`, `_settled_belief`, `_desired`, `_send_reason` (including the `ignore` rule), `_apply`, `_send`, `_after_send`, `_refresh`.
- **Proof of arrival:** in-flight marks with `value/from/earlier/earlier_until/until`, extended and never replaced. `_arrived` is the only arrival test, and `_prove` re-reads until a reading proves it.
- **Signals:** `_edges` and `_fire`, with `entered`/`leaving` and rule-signal keys `step:<action>:<n>`.
- **Slots and abort:** `_close_slots` (closed, explained, final, orphan) and `_held_already` / `_rollback` with `rollback_of`.
- **Reconcile:** `reconcile_tick`, `_reconcile_apply`, `reconcile_once` and per-subsystem loops. Enforce re-asserts once then reports `overridden`; retries back off 30 s, 1, 2, 5, 10 min, then give up; health recovery restarts given-up retries; the generation check drops stale ticks.
- **Restart:** `start()` per §4.9.
- **Hand changes:** `hand_set` / `_hand_apply`; `set_target` is kept as a thin alias that awaits the result. Also `assume`, `stored_edit`, `stored_restore`, `stored_forget`.
- **Reload:** `reload` / `_reload_now`. Nothing moves, `pending_targets` are listed, and a reload during a transition is applied when it ends.
- **Views:** `status()` per §7.1, plus `describe()` and `plan(config=)`, both updated.

**`roomstate/fakes.py`**
- `FakeLevel` has the §8 knobs: `cancel` (`keep_moving` by default), `stale_until_stop`, `retarget`, `readback_lag_s`, `reports_moving`, `hang_apply`/`hang_read`, `cancel_cleanup_s`, `swallow_cancel`, `offline`, `fail`, `persist` with `restart()`, plus `refuse`.
- Its `apply()` is deliberately naive: it can be fooled by a stale cache, so the coordinator's proof has to catch it.
- Also new: `FakeScreens` (entry handshake: abort before `go`, complete-then-exit after `go`, in-stream patch, `give_up()`), `FakeEdge` with `offline` and `delay_s`, `FakeSignals`, `Clock` and `hard_kill`.

**`roomstate/model.py`** (one fix)

**`rfspike/bloc_hub.py`, `BlocBlinds`** (BlocHub's protocol code is untouched)

### Deviations from the spec
1. **Reserved sources:** `request_mode` itself raises `Refused("bad_source")`, and `start()` calls an internal `_request`. This lets the API map one exception, and gives room_service a path for its own sources.
2. **Fewer saves:** `_store`, the save after appending to `leaving`/`entered`, and `_send`'s final save are left out, and row updates are saved once per batch. Each of these is still on disk before the next send, which is what §3.4 needs.
3. **Health recovery restarts only retries that gave up** (§4.1's wording), not every unsettled retry (§4.12). Otherwise a hub whose reads work and writes fail would reset its backoff on every tick.
4. **Edge health:** only an exception or a failed read marks a subsystem unavailable; an `ok` apply marks it available. An edge can't be read, so the S9 test calls `_health(..., ok=True)` to stand in for "the RM4 is back".
5. **Backoff index:** the spec's `BACKOFF[attempts]` runs off the end after the 5th attempt; I use `min(attempts, 4)`. Toggles are also never retried by reconcile; §4.8 says so in prose, but its pseudo-code doesn't check for them.
6. **`explained`** is computed in `_apply` before the send (item 10) and includes the mark's own commanded value. `_apply` takes `mode=` for the adapter opts, because the spec's `merged_opts` is undefined.
7. **`_fire(tr, sig, row, key)`** takes the row and the computed key, because a Step from the config can't carry a per-transition row.
8. **New `transition.notes`:** `_note` (used in §4.4) has no field in §3.3. `plan()` returns notes such as "nothing stored: leave", which keeps aa's "why" now that rows exist only for commands, signals and delays.
9. **No rows for exit signals that already fired:** an exit signal of a mode already in `leaving` gets no row.
10. **`hand_set` and `assume`:**
    - `hand_set` returns the running task (the 202) and refuses placeholder or dry-run targets with a new code, `unavailable`.
    - `assume` on a level target raises `Refused("readable")`; the spec says 409 but gives no code.
11. **Deferred reload:** a reload during a transition returns `deferred: True` and is applied in `_run`'s `finally`, after a cancel too, so the next request uses it.
12. **Plumbing:** `start(reconcile=True)` takes a flag. The state is loaded in `__init__`, as aa did, not in `start()`. `margin_s`, `cleanup_s` and `signal_timeout_s` are constructor arguments; the defaults are the spec's 15, 3 and 5 s.
13. **Writes and status:**
    - Reconcile ticks compare state without reading times, so ticks that re-read unchanged values don't write.
    - Status shows `orphan` as soon as a reload makes an entry unused.
    - `_close_slots` clears `orphan` if a config uses the entry again.
14. **R6 test:** the §8 description says "offline 30 min: 5 tries", but §4.8 skips stale beliefs, so retries can't run while reads fail. The test models it as the writes going missing (reads still working) for the five tries, then a read outage and return.
15. **S9 abort detail:** it also names `blinds.ch14`. R7 re-sends stale values, so ch14 fails too; the S9 text names only ch02 and ch03.

**aa test expectations changed to match the spec** (each marked "v1.1:" in the test):
- Sonos playback is state, not a play/pause signal; ambient retrieves Sonos.
- The "already fired" check uses live's `on_exit` instead of `sonos.pause`.
- An unreachable hub now leads to a rollback.
